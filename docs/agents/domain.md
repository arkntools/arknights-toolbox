# 领域文档

采用 single-context 布局：

- 根目录 `GLOSSARY.md`：领域术语。
- 根目录 `docs/adr/`：架构决策记录。

## 探索代码前

读取现有 GLOSSARY.md，以及与当前工作相关的 ADR。

文件不存在时直接继续。术语或决策得到明确结论后，
由 domain-modeling 技能按需创建领域文档。

## 使用领域术语

任务标题、重构建议、假设和测试名称使用术语表定义的名称。

所需概念尚未收录时，判断是否误用了项目之外的说法；
确有缺项则留给 domain-modeling 处理。

## 架构决策冲突

输出与已有 ADR 冲突时，明确指出对应 ADR 及重新讨论的理由。
